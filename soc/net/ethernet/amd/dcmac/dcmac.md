# AMD/Xilinx DCMAC - SystemC/TLM-2.0 model

## Introduction

The AMD/Xilinx Versal 600G Channelized Multirate Ethernet Subsystem
(DCMAC) is a high-performance, adaptable, Ethernet-integrated hard IP
that targets numerous customer networking applications.

More information about it is available here [PG369].

The dcmac-regs.h is auto-generated by the dcmac-reggen.py script.
See the script for detail as well as the data-source retrievable
via [PG369].

## Model dcmac-eth

This model emulates DCMAC operating in the Coupled MAC+PCS
(FixedE) mode. The model includes all 6 FixedE ethernet macs.

This model emulates port data rate (see [PG369] Port Data Rate) by
disabling macs that are made unavailable due configured data rates
of other macs.

### Current status

The model's ports and interfaces have been finalized. The internal
functionality in the model is under development.

In its current state, the model can be used for early integration into
simulation platforms as a non-functional model but with correct interfaces.
Eventually, it will be possible to drop-in replace the non-functional model
with an updated version that provides functionality.

### Accuracy

This is a functional LT TLM-2.0 model. It is not cycle accurate and
it abstracts away many low-level details in the communication.

The PCS is modelled very abstractly. There won't ever be any errors,
the link is always up and there's no training or such low-level
details going on.

### Device-level Ports

| Port           | Description |
|----------------|-------------|
| reg_socket     | APB memory-mapped interface where the MAC will respond to register accesses |
| rst            | Reset signal for entire device                                              |

### Per-mac Ports

| Port           | Description |
|----------------|-------------|
| mac_rx_socket  | AXI4-Stream channel where the MAC will send packets towards user-logic       |
| mac_tx_socket  | AXI4-Stream channel where the MAC will recieve packets from the user-logic   |
| phy_tx_socket  | GTM/GTY interface where the MAC will send packets towards physical layer     |
| phy_rx_socket  | GTM/GTY interface where the MAC will reieve packets from the physical layer  |
| reg_socket     | APB memory-mapped interface where the MAC will respond to registrer accesses |
| rst            | Reset signal                                                                 |

####  GTM/GTY interfaces

The interface towards the GTM/GTY is modelled by a TLM socket.
Generic payloads carry Ethernet frames. These frames are raw Ethernet frames without
any particular encoding or FEC.

#### AXI4-Stream interfaces

The AXI4-Stream interfaces towards the user-logic are modelled as TLM sockets using
libsystemctlm-soc's generic attributes to signal AXI4-Stream's TLAST signal as EOP.
libsystemctlm-soc's generic attributes is an optional TLM-2.0 extension [genattr].

### Limitations

See current model status above.

The model does not emulate the IEEE 1588 Timestamping features.
The model does not emulate FEC.
